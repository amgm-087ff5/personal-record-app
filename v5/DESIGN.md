# 個人記録 UI v5 — 設計書と意味表

v5 は「UI/UXデザイン標準 第1版」(Claudeプロジェクト資料 `claude/ui-ux-design-standard.md` / Notion https://app.notion.com/p/4130e0548622819f9c03d90069990029)に沿って、HTMLモック v4 を一から作り直したもの。
**規則: ここに意味が書かれていない見た目は使わない。新しい見た目は、先にこの表へ意味を書いてから作る。**
具体的な色・影・角丸・文字・余白の値は `css/tokens.css` だけに置く。

---

## 0. v5 の約束(v4 から退化させない・必ず進化させる)

- v4 の全画面・全機能・全操作を残す(棚卸し `/home/claude/inv/I1〜I6.md` が基準。v4 のコードは `v4/` にある)
- v4 で利用者が「良い」と評価した表現は、形を保ったまま磨く(9章)
- v4 で「モックでは未対応です」のトーストだけだった操作は、v5 では実際に動かす(3章)
- v4 の不具合(4章)は全て直す
- 本番アプリ(`app/`)と `v4/` は変更しない

## 1. 情報構造

### 1.1 ドメイン(データモデルをそのまま画面に)
- **日**(日記)が最上位。その中に **活動**(期間)と **瞬間**、活動の中に子の活動や **支払い**
- **支払い** = 起きた事実(誰がいくら払ったか・誰が何を使ったか)。アクティビティの1つ
- **支出** = 家計簿のエントリ(支払いのうち自分の負担と、その分類)。支払いの子として半券で表す
- **予定** = まだ起きていない出来事。**支払い予定** = 予定の一種(固定費など)。**ToDo** = やること(予定の子にもなる)
- **エンティティ**(縁) = 人・場所・会社・物・書類・プロジェクト。時間をまたいで続く。種類は階層(種類の木)
- **メモ** = すぐメモ(日時つきの短い文) / エンティティのメモ(縁に綴じた長文。主観・最新、版を持つ)
- **カテゴリ** = 支出の分類(階層。固定/変動・日常/非日常の既定を持つ)

### 1.2 ナビ(v4 と同じ。評価済み)
- 1枚目(毎日): ホーム / アクティビティ / ＋ / ToDo / メモ
- 2枚目(整理): エンティティ / 家計簿 / ＋ / 設定 / (空き)
- ＋は中央で動かない。切替はつまみのタップ・縦ドラッグ・横スワイプ。ドラッグは指に近い窓から先に動く(11/05「とても良い」)。タップの切替は左から順の遅延アニメ(残す)
- 幅900以上: 左のレールに7タブ。幅1100以上: 一覧+詳細の2列(v4 と同じ)

## 2. ファイルと共通の仕組み(実装の約束)

```
v5/index.html            読み込み順: tokens.css → base.css → parts.css → screens/*.css → data.js → plans.js → money.js → core.js → parts.js → screens/*.js → 起動
v5/css/tokens.css        値の唯一の置き場(本体が作成済み)
v5/css/base.css          リセット・レイアウト・ナビ・シート・トースト(core 担当)
v5/css/parts.css         共通部品の見た目(parts 担当)
v5/css/screens/<名前>.css 画面ごとの見た目(画面担当。色・影・角丸・文字の値は tokens の変数だけ)
v5/js/data.js plans.js money.js  データとお金の計算(v4 から移し、4章の不具合を直す)
v5/js/core.js            保存・ルーター・ナビ・シート・トースト・作成の登録・小道具
v5/js/parts.js           共通部品(HTML を返す関数)
v5/js/screens/<名前>.js  画面
v5/tools/audit.py        機械点検
```

- グローバル関数で書く(ビルドなし。v4 と同じ)。関数名は衝突を避けるため、画面固有のものは画面の接頭辞を付ける(例 `hm`・`tl`・`dt`・`pl`・`lg`・`cr`・`en`・`mm`・`st`)
- 文字は全て `esc()` を通す。HTML の中の onclick には id だけを渡す
- 状態の保存は localStorage キー `prmock-v5`(v4 と別)。テーマは `prmock-theme`

### 2.1 core.js の API(core 担当が作る。画面担当はこれだけを使う)
| 名前 | 中身 |
|---|---|
| `TODAY` `NOW` | 固定の今日 `2026-10-31`・いま `13:20`(data.js の TODAY を使う) |

| `fmtMD(d)` `fmtMDW(d)` `dowJ(d)` `relDay(d)` `minsBetween(a,b)` | 10/31 / 10月31日 土曜 / 土 / 今日・昨日・n日前・n週間前・nか月前 / 分 |
| `save()` `load()` `resetData()` `exportData()` | 保存(全体を JSON)/ 読み込み / 初期化 / 全データを JSON ファイルで書き出す |
| `route(name, fn, {tab})` | 画面の登録。fn(id, q) は HTML 文字列を返す。描いた後の処理は `after(fn)` |
| `go(hash)` `goBack()` `parseHash()` `render()` `rerender()` | 遷移 / 戻る(履歴なしは #/home)/ 解析 / 描画 / 同じ画面をスクロール位置を保って描き直す |

| `setSheetBody(html)` `closeSheet(force)` `sheetOpen()` | 中身の差し替え(スクロール保持)/ 閉じる / 開いているか |
| `toast(msg, {undo})` | 結果の通知。undo があれば「取り消す」(6秒)。複数は順に積む(前の取り消しを消さない) |
| `confirmIn(o)` | 取り消せない操作だけの確認(シートの中に出す)。o = {title, body, ok:{label, danger}, on} |
| `addCreate({key, label, icon, primaryOn:[tab], run})` | 作成の一覧(＋)に登録。今のタブで primaryOn に入るものが先頭の主行 |
| `currentTab()` | 今のタブ |
| `NAV` の描画 `renderNav()` | v4 の動きを移す(1.2) |
| `hapt()` | 対応端末で軽い振動 |

## 3. 進化(v4 から必ず良くする所)

### 3.1 全画面
1. **シート**: 下スワイプで閉じる。入力中なら破棄の確認。✕は常に左上(標準3.9)
2. **トースト**: 取り消しを積む(前の取り消しが消えない)
3. **行き止まりをなくす**: v4 で「モックでは未対応」だった操作を全て動かす
   - エンティティの編集(名前・種類・項目の値・関係)と削除(取り消し)
   - 種類の追加(「＋種類」)、種類の項目の追加・名前変更・削除
   - エンティティのメモの編集(見出しと本文、保存で版+1・更新日時)、サブページの追加と開閉
   - 予定の編集(題・日時・終日・場所・参加者・繰り返し・通知・メモ)と削除(取り消し)
   - 記録(期間・支払い)の時刻・題・役割の編集
   - 支出の詳細の「その他」(カテゴリ・特別感・固定/変動・メモの編集)
   - すぐメモの編集・ピン留め・削除(取り消し)
   - 品目の削除(取り消し)
4. **空の状態**: 全ての一覧に `empty()`(何もないこと+最初の一手)
5. **読み取り値と確かめた値を区別**: レシートから読んだ値は `readMark()` 付きの淡い表示。利用者が確かめて「確定」すると塗りになる。読めなかった値は空欄で目立たせる(推測で埋めない)
6. **全データの書き出し**(設定): JSON をダウンロード。読み込み(復元)も
7. **読み上げ名**: 言葉なしのアイコンボタンに aria-label
8. **値は tokens だけ**: 画面CSSに色・影・角丸・文字サイズの直書きをしない

### 3.2 画面ごと(主なもの。詳細は各担当の指示)
- ホーム: 支出の比較の言葉を「先週の◯曜」に正しく(曜日を計算)/ 終日の予定も「今日の流れ」に出す / すぐメモはピン留めを先に(メモ画面と同じ並び)
- タイムライン: 絞り込みを日のページに漏らさない / 件数の数え方を揃える(直下の記録の数)
- ToDo: 「今日」の件数の数え方を揃える(期限が今日以前の未完了)
- エンティティ: 「一緒の時の自分の支出」に親の活動の中の支払いも含める / 検索は名前・種類・項目の値(略称など)で探せる
- 家計簿: 税率の既定を10%に統一し、支出の品目にも税率を出す / 品目の最後の1件を消せる(エラーにしない)
- 設定: 初期化の確認文を「全てのデータ(記録・予定・メモ・エンティティ・カテゴリ)」と正しく書く / 削除・初期化の文字に赤を使わない(赤は いま・遅れ だけ)

## 4. 直す不具合(棚卸しで見つかったもの)
- タイムラインの絞り込みが #/day に漏れる(I2)
- ToDo の「今日」の件数がまとめとチップで違う(I2)
- 件数の数え方が一覧と日のページで違う(I2)
- 品目の削除の入口がない・最後の1品目の削除でエラー(I2・I3)
- エンティティの「一緒の時の自分の支出」が過小(I4)
- データの不整合: 家賃(銀行振込)の支払い方法、健さん払いのランチの支払い方法が空、ToDo の `pay`(支払いid)と支払い予定の `pay`(金額)の鍵の衝突(ToDo 側を `payRec` に改名)(I4)
- 種類の削除の取り消しが保存されない(I4)
- メモの日時に年がない(並び順が年をまたぐと崩れる)(I4)
- 「先週の土曜」の固定文字(I1)/ 終日の予定がホームに出ない(I1)/ すぐメモの最新がピン留めを無視(I1)
- 初期化の確認文が実際と違う・赤の誤用(I1)
- 税率の既定が画面ごとに違う(I3)
- シートの footer と主ボタンの穴(I5)
- トーストの取り消しが上書きで消える(I5)

## 5. 意味表(見た目 → 意味)

### 5.1 面
| 見た目 | 意味 | なぞらえる元 |
|---|---|---|
| 地(--bg、うっすら青み+窓辺の光) | 記録が置かれる地面 | 窓辺の机 |
| 影のある白い面(--e1) | 1つの独立したオブジェクト。押すと開く | 机に置いた紙 |
| 影の濃い面(--e2) | このページの主役 | 手に取った1枚 |
| 浮いた面(--e3) | 内容の上に浮く操作(＋・シート・トースト) | 手に持った道具 |
| 影のない枠線の面 | 主役の属性・部分の集まり。中の行はオブジェクトではない | 1枚の紙の欄 |
| 1つの面の中にまとめたもの | ひとかたまりとして扱う | 束ねた紙 |

### 5.2 形
| 形 | 意味 | なぞらえる元 |
|---|---|---|
| カプセル 塗り | 起きた出来事(時間上の点) | 押したスタンプ |
| カプセル 点線・中抜き | 予定(まだ起きていない) | 鉛筆の下書き |
| カプセル 赤の点線 | 過ぎたのに記録になっていない予定 | 期限切れの札 |
| 半券(切れ込み+点線) | 自分の支出(支払いから切り取った自分の分) | 切り取る券 |
| 半券の左「日常」/「✦ 非日常」 | 支出の特別感(色ではなく印) | 券の種別欄 |
| 白い横長のカード(輪郭が発光) | 日の区切り・1日のページの入口 | 日めくりの1枚 |
| 角丸の正方形の枠 | ToDo。塗り=完了 | チェックボックス |
| 緑のドット | エンティティ(自分以外)。中抜き=未登録 | 地図のピンの頭 |
| 角を折った紙 | メモ | 付箋・紙 |
| ひし形 | エンティティの事実が変わった・関係が始まった時点 | 目印の杭 |
| 横の棒(区間に分かれる) | 1つの支払い・1か月の支出の金額 | 帯グラフ |
| 斜線(琥珀) | 立替で未精算のお金(この意味だけ) | 未済の印 |
| 縦の細いガイド線+字下げ | 分類の階層(種類・カテゴリ・タグの入れ子) | 目次の字下げ |
| 入れ子の面 | 親子(日 › 活動 › 支払い) | 封筒の中の書類 |
| ピル(丸い錠剤形) | 操作(絞り込み・切替)。データには使わない | ボタン |
| タグ(角丸6の小さい四角) | データに付いた分類 | 値札 |

### 5.3 色(1色=1意味)
| 色 | 意味 |
|---|---|
| 青 --me | 自分(自分の分・自分の操作・今日) |
| 青灰 --ev | 起きた出来事の塗り |
| 青緑 --kin | 縁(自分以外のエンティティ) |
| 灰 --plan(点線) | 予定・未来 |
| 赤 --late | いま・遅れ・期限切れ(この意味だけ。削除や初期化に使わない) |
| 琥珀 --owe | 貸し借り・未精算 |
| 淡い青灰 --unread | 読み取った値(未確認) |
| カテゴリの色 | 利用者が決めたデータの色。カテゴリの横棒と棒の区間だけ。淡く |
| 使わない | 墨(黒に近い濃色)・茶色・紫・白い背景の上の濃いグラデ |

### 5.4 線
| 線 | 意味 |
|---|---|
| 縦の実線(灰) | 過去の時間軸 |
| 縦の点線(灰) | 未来の時間軸 |

### 5.5 強さの順位(画面ごと。同じ強さを並べない)
| 画面 | 1位 | 2位 | 3位 |
|---|---|---|---|
