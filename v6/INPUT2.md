# v6.3 入力 2 — 区切りで読む・全画面・記録モード(設計と契約)

2026-11-12。前提は INBOX.md(v6.2)。ここに書いた所だけを変える。

## 0. ねらい(利用者の要望と、その奥)

| 要望 | 奥にある困りごと | 方針 |
|---|---|---|
| 1行ごとに区切れば精度が上がるのでは。「今日は楽しかった」が今日の予定(ToDo)になる。でも音声では改行できない | 機械が勝手に読み違えた記録が増えるのが嫌。区切りを入れる手間も嫌 | **区切り=改行・空白・読点・音声の間(ま)** を同じものとして扱う。区切られて独立した語だけを「項目」と読む。文の中の語は項目にしない。読みに **強い/弱い** を付け、勝手に未確定の記録にするのは強い時だけ |
| 入力画面は全画面のモーダル。入力欄に焦点がある間は記録モード | 急いで書く時に、履歴や他の物が目に入ると邪魔。種類選びと入力だけに集中したい | シートを全画面に。**記録モード**(焦点あり)と **履歴モード**(焦点なし)を切り替える |

プラスアルファ(今回入れる):
- **読み取りの見える化**: 記録モードで「こう記録します」の札を常に出す。読んだ語(日付・時刻・金額)は札の中の小さな札で見せ、**押すと取り消せる**(その語は文の一部に戻る)
- **区切りを打つ道具**: キーボードの上に「今日 / 明日 / 時刻 / 円 / 改行」の1タップの列。改行を打ちにくい端末でも区切れる
- **音声の間=改行**: 話の切れ目(認識の確定の単位)を改行にする。「改行」と言っても改行になる
- **感想は日記へ**: 「今日は楽しかった」のような感想の文は、予定にもToDoにもせず「日記に書く」を勧める(強制しない)
- **空行=記録の区切り**: 空行で分けると複数の記録として一度に置ける

## 1. 読み取り(担当 A: js/m-inbox.js)

### 1.1 契約

```
readText(text, base, o = {}) → {
  cand,   // 候補(INBOX.md の cand と同じ形。type: pay|plan|event|task|memo)。読めなければ null
  conf,   // 'strong' | 'weak' | 'none'
  marks,  // [{ role:'date'|'time'|'amt'|'type', word, label }]  読み取った語(画面の札に出す。label は「明日」「10:00」「¥850」「予定」など)
  off,    // [{ role, word, label }]  o.off で取り消した語、または文の一部と判断して採らなかった語
  hint,   // 'diary' | null   感想の文
  hintDate // hint='diary' の時、どの日の日記か(文中の日付の言葉。無ければ base.date)
}
```
- `base = {date, time}` 既定の日時(無ければ今)。`o.off = ['date','time','amt','type']`(配列。B は Set を配列にして渡す)の役は読まない(ただの文字として扱う)
- **conf が weak でも cand は返す**(画面は点線の札で見せ、「記録する」で記録できる。勝手には記録にしない)
- `o.type` を渡すと、その種類で読み替える(必ず cand を返す。conf は 'strong')。項目の読み方は下の決まりと同じ(文の一部の日付は外さない。題は元の文のまま)
- `ruleCandidates(text, base)` は **`conf === 'strong'` の時だけ `[cand]`**、他は `[]` を返すよう直す(=勝手に未確定の記録にするのは強い読みだけ)。`candFromType` の形は変えない
- `readBlocks(text)` → 空行(2つ以上の改行)で分けた文の配列(前後の空白を除き、空は捨てる)。**1つの文(ブロック)= 1つの記録**。ブロックの中の改行は区切り(項目の境目)
- `jotAddMany(texts, o)` → 複数の雑記を **commit 1回** で置く(各文は jotAdd と同じ扱い: 強い読みは未確定の記録まで作る)。`{ok, ids, undo, label:'n件を置きました'}`。取り消し1回で全部戻る
- `diaryAppend(date, text)` → commit 1回で `DB.days[date].diary` の末尾に改行して足す(`daySetDiary` を使ってよい)。`{ok, undo, label:'日記に書きました'}`
- 全て `Object.assign(window, {...})` で出す(const の関数は window に載らないため)

### 1.2 決まり

0. **感想の文は最初に見分ける**: 文末が感想の言葉(〜かった / 〜だった(名詞+だった を除かない) / 楽しみ / 疲れた / 眠い / 〜たい / 嬉しい・悲しい・美味しい 等の形容詞の言い切り)なら、日付の言葉や助詞に関係なく cand=null, conf='none', hint='diary'。ただし金額(円・¥)があれば支払いが勝つ
1. 文を **区切り**(改行、半角/全角の空白、、。)で切る
2. **区切りがまるごと** 日付の言葉・時刻・金額・種類の言葉(予定/ToDo/メモ/支払い/出来事)の時は項目(強い)
3. 区切りの **先頭** に日付・時刻があり、続きが「に」「から」「、」か名詞・動詞の時も項目(音声は空白が入らないため)。例「明日10時に歯医者」
4. **文の一部** の日付: 日付の言葉のすぐ後が「は」「も」「って」「の」の時は、独立した項目でない → 読めても **weak**(例「明日は歯医者」= 予定 weak、「昨日は病院に行った」= 出来事 weak)。題は元の文のまま
4b. 題 = 項目でない区切りを空白でつないだもの。先頭に残った助詞(に・は・から・、)は外す。**題が空なら cand=null, conf='none'**(「今日」だけ、など。金額だけの支払いは例外で可)
5. 金額は「円」「¥」が付いていれば文中でも強い。数字だけ(3桁以上)は、区切りがまるごと数字の時だけ。ただし 1900〜2100 の4桁(年に見える数)は金額にしない。「N時間」は時刻でない。支払いの日付は今日以前だけ(先の日付の言葉は off に入れ、今日にする)
6. 種類の決め方は今の parseQuick に準じる(金額→支払い、先の日時→予定、過去の日時→出来事、#→ToDo)。加えて: 独立した先の日付 + 時刻なし + 文末が動詞の終止形(買う/出す/行く/する 等)→ ToDo(期限つき)
7. 手がかりが無い文は cand=null, conf='none'(雑記のまま)

## 2. 画面(担当 B: js/s-inbox.js, css/s-inbox.css)

### 2.1 全画面のモーダル
- `.sheet-wrap[data-id="inbox"]` のシートを画面いっぱいに(高さ 100dvh、角丸なし、上の隙間なし、安全域は padding で)。幅 900px 以上は中央の大きな枠(幅 min(720px, 92vw)、高さ min(92dvh, 900px)、角丸あり)
- モーダルのまま: × で閉じる、下に引いて閉じる動きは止める(全画面のため)。scrim は見えなくてよい
- 位置は `position:fixed; inset:0` だけ。高さは `calc(100dvh - var(--kb,0px))`(`--kb` は js/kbd.js が入れる、キーボードに覆われる高さ。Android は画面ごと縮むので 0)。**既存の `inVV`(top / height を直に書く)は消す**。安全域は env() の padding。入力欄と下の操作列が必ず見える

### 2.2 2つのモード(`.in-wrap` に `is-rec` を付け外し)
- **記録モード** = `#in-t` に焦点がある間。＋で開いた直後は記録モード
- **履歴モード** = 焦点がない時。今の画面(帯・履歴・絞り込み・選ぶ)
- 記録モードの中のボタンは `pointerdown`(と mousedown / touchstart)で `preventDefault` して焦点を奪わない。焦点が外れた時は **150〜200ms 待って** `document.activeElement` を見てから履歴モードへ(iOS で押す前に切り替わって click が消えるのを防ぐ)
- 記録モードを出る: 見出しの「履歴」ボタン(未処理の件数つき)、× は閉じる。履歴モードで下の入力欄を押すと記録モードへ
- 切り替えは描き直しでなく class の付け外しで。**入力欄(#in-t)はシートが開いている間 1度も作り直さない**(今の `inRedrawAll` の `setSheetBody(inBody())` は入力欄ごと作り直すので、履歴・帯・補助の所だけを差し替える形に直す。選ぶ/完了も同じ)

### 2.3 記録モードの並び(上から)
1. 見出し: × / 「記録」 / 「履歴 n」
2. **種類の列**: 「自動」+ 支払い・予定・出来事・ToDo・メモ・日記(横に流れる chips)。自動の時は読み取った種類の札が点線(--read)で光る。押すとその種類で決め打ち(`readText(text, base, {type})`)。日記は `diaryAppend`
3. **入力欄**: 大きく(残りの高さを使う。字は --fs-input 以上)。placeholder は短い例
4. **「こう記録します」の札**: 種類の印・題・項目の小札(marks)。小札を押すと取り消し(off に移り、薄い札として残る。もう一度押すと戻る)。小札は押せる面が 44px 以上。札は `aria-live="polite"`。conf が weak の時は札全体が点線(--read)。none の時は「雑記のまま置きます」。hint=diary の時は「日記に書く」のボタン。複数の記録(空行区切り)の時は「n件」と各行の要約
5. **道具の列**(キーボードのすぐ上): 今日 / 明日 / 時刻 / 円 / マイク。押すと入力欄のカーソル位置に、前後を区切って差し込む(「時刻」は今の時刻 HH:MM、「円」は数字の後ろに付く)
6. **操作の列**: 「雑記に置く」(副)・「記録する」(主)。記録するは cand がある時だけ押せる(pay で金額なしは不可)。置いた後も記録モードのまま、入力欄は空に、結果は1行で出し「取り消す」を付ける(既存の in-undo)
- 細かい入口(レシート・エンティティ・詳しい編集)は、種類の列の右端の「ほか」から(既存の inKinds の中身を pick かシートで)

### 2.4 動き
- 取り消した役は `IN_OFF`(Set)に持ち、入力が空になったら消す
- 「雑記に置く」= 今の inSend。空行で分かれていれば `readBlocks` の各文を1回の commit でまとめて置く(取り消し1回で全部戻る)。「記録する」も各文をそれぞれ記録(読めない文は雑記として置く)
- `readText` が無い時(A が未完成)でも落ちない: `typeof readText === 'function'` で確かめ、無ければ今の inCand の動き
- 既存の公開関数(openInbox, inRefresh, openCapture, capOpen, capAs, capSave, capRefresh)と id(#in-t, #in-log, #in-send, #in-mic, #in-aux)は残す。既存のテスト `/home/claude/tools/t_ui.py`(16件)が通り続けること(ボタンの語が変わる所はテスト側を直してよい。理由を報告)

## 3. 音声(担当 C: js/voice.js, css/voice.css)
- 認識の確定の単位(isFinal の1件)どうしは **半角の空白** でつなぐ(日本語の認識結果には空白が無いので、話の間(ま)が区切りになる。読み取りでは空白も改行も同じ区切り)
- 認識の再開(onend → 次の認識。長い無音)の境目は **改行**
- 「改行」「かいぎょう」とだけ話した確定は、文字にせず改行にする。2回続けば空行(=次の記録)
- 今の `vcText()` は `\s+` をまとめて改行を潰すので、改行を保つよう直す(空白の連続だけまとめる)
- composer(入力欄のマイク)の時は、確定のたびに `onText(確定した1件, {live:1})` を呼ぶ(話しながら札が変わる)。**終わった時に全文をもう一度渡さない**(二重に入る)。入力欄側(B の `inAppend`)は、前が空でなければ空白を挟んで足す。改行だけが来たら改行を足す
- nav(＋の長押し)は今のまま、終わった時に全文を置く。空行があれば `jotAddMany(readBlocks(text))`(無ければ jotAdd)
- 録音中の表示(#voice-pill)は全画面のシート(z-index 50)より上に出す
- 既存の公開関数と `window.__speechMock` の形は変えない
