## 0. 要望の整理

| # | 要望 | 方針 |
|---|---|---|
| 1 | 改行はアイコン。音声ボタンを真ん中、右に改行、左になんらかのボタンの3ボタン構成。**(追加)改行マークの横に ¥ 等のボタンも** | 下の1列に **[左: 日付の行(カレンダー)][中: 音声(大きい丸)][右: 改行 ↵・金額 ¥・タグ #]**。右の3つは押すと **新しい行を作って、その行の頭に記号を入れる**(¥ → 改行+「¥」、# → 改行+「#」、↵ → 改行だけ)。カーソルが空の行にある時は改行を足さず記号だけ入れる。左は「日付の行のショートカット」の列(今日 明日 +0 +1 /日 時刻)を開閉する(押すと入力欄のすぐ上に出る)。道具の列の常時表示はやめる |
| 2 | 記録モードで、焦点が外れても履歴モードに戻さない | 焦点の外れで切り替える処理を **消す**。記録⇄履歴は見出し右のボタンだけで切り替える(記録モード中は「履歴 n」、履歴モード中は「記録」)。履歴モードで入力欄を押す(焦点が入る)と記録モードに入るのは今のまま。＋で開いた直後は記録モード |
| 3 | 履歴: 確定済みは横長のカード。確定ボタンなどはカードの下の外へ | 作った/直した/消した の行を **横幅いっぱいのカード** に。雑記の吹き出しの中に入れていた「未確定の記録」も **吹き出しの外** に横長の点線カードとして出し、そのボタン(確定・直す)も、雑記の操作(変換する・メモにする・LLMで変換)も、**カードや吹き出しの下の外側** に置く |
| 4 | 記録モードの構成: ①記録予定のカードビュー ②種類 ③確定ボタン・下書き保存ボタン ④入力欄(高さは3行で固定) ⑤音声ボタン・改行ボタンなど | 上から ①〜⑤ の順に固定。①が残りの高さを使って縦にスクロール、②〜⑤ は固定の高さ |
| 5 | **やはり文章中ではなく、改行でプロパティの区切りとする**(例: 1行目「10/30の買い物」=題。2行目「/10 19:30」=今月10日19:30、3行目「+0 20:30」=同じ日(+0日)20:30) | 読み取りを **行ごと** に作り直す。1行目=題(中の日付や数字は読まない)。2行目以降=プロパティの行(日付・時刻・金額・タグ・種類)。形が合わない行は備考として残す。詳細は §5。音声は話の間(ま)=改行にして、改行で区切る書き方と両立する |

### 言葉の決め
- 「確定」= 今の「記録する」(読み取った候補をその場で確定した記録にする)。履歴の未確定カードの「確定」と同じ語・同じ意味
- 「下書き保存」= 今の「雑記に置く」(`inSend`。強い読みなら未確定の記録も一緒にできる。それも下書き)。**ボタンの語だけ変える**。履歴の絞り込み「雑記 n」などの語は変えない(本体の判断。利用者に確認する)

## 1. 記録モードの並び(担当 B1: js/s-inbox.js の記録側、css/s-inbox.css、js/parts.js)

```
┌ 見出し: ×  記録  ……  [履歴 n]
├ ① 記録予定のカードビュー   (#in-cards。flex:1 で残りの高さ。縦スクロール)
├ (取り消しの1行 #in-undo。出た時だけ)
├ ② 種類の列                 (#in-kinds。横に流れる)
├ ③ [ 確定 ] [ 下書き保存 ]    (#in-ops。2列均等、どちらも44px以上)
├ (日付の行のショートカットの列 #in-ins。左ボタンで開いた時だけ。今日 明日 +0 +1 /日 時刻。入力欄のすぐ上)
├ ④ 入力欄 #in-t              (3行ぶんの高さで固定。中だけスクロール)
└ ⑤ [日付] [ 🎤 音声 ] [↵][¥][#]  (#in-tools。中央が大きい丸。左=日付の行のショートカット、右=行を作って記号を入れる)
```
- ①が空の時は、カードの代わりに点線の枠(`--read` の線)に「記録予定」とだけ出す(説明文は置かない)
- 並べ替えは **CSS の order** で行う(DOM の作り直しはしない。`#in-t` は開いている間 1度も作り直さない)。履歴モードの見た目(1行の入力欄・マイク・送る)は今のまま
- ⑤の音声は履歴モード用の `#in-mic` と別に **記録モード用のボタン `#in-mic2`** を置き(`inMic()` を呼ぶ)、`inMicPaint` は両方の状態(is-rec / aria-pressed)を更新する。記録モードでは `.in-row` の `#in-mic` と `#in-send` は隠す
- 左(日付の行): `aria-label="日付・時刻の行を入れる"`、アイコンは `calendar`(parts.js の `IC` に無ければ足す)。押すと `#in-ins` の表示を切り替え(`aria-expanded`)。`#in-ins` のボタンは `inTool(k)`: `today`→行「今日」、`tomorrow`→行「明日」、`same`→行「+0 」(同じ日。時刻を続けて打つ)、`next`→行「+1 」、`day`→行「/」(日を続けて打つ)、`time`→行「HH:MM」(今の時刻)。いずれも「新しい行を作ってその文字を入れる」(カーソルが空の行ならその行に入れる)。入れても列は開いたまま
- 右の3つ(改行・金額・タグ): `aria-label` は「改行」「金額の行」「タグの行」。改行は新しいアイコン `enter`(向きは「↵」)、金額は文字「¥」、タグは文字「#」(アイコンにせず文字でよい)。押すとそれぞれ `inTool('nl')` / `inTool('yen')`(行を作って「¥」を入れる。数字を続けて打つ) / `inTool('tag')`(行を作って「#」を入れる)。3つとも 44px 以上。360px 幅で ⑤ が1行に収まる(左44 + 中央56 + 右3つ)
- 入力欄の高さ: 記録モード中は 3行ぶん固定(`height: calc(var(--fs-input) * 1.6 * 3 + var(--s3) * 2)`、`overflow-y:auto`、`resize:none`)。`inGrow` は記録モード中は何もしない(履歴モードの1行ぶんの自動伸びは今のまま)
- 焦点: 押しても焦点を奪わない仕組み(`inGuard` の pointerdown / mousedown の preventDefault)は今のまま、新しいボタン(#in-mic2、差し込み、改行、確定、下書き保存、種類、差し込みの列、カードの小札)も含める
- モード切替(`inWire` / `inRecOn` / `inToHist`): `blur` で履歴モードへ戻す処理(`IN_BLUR_T` を使う所)を削除。`focus` で記録モードに入るのは残す。見出し右のボタンは、記録モード中=「履歴 n」(`inToHist`)、履歴モード中=「記録」(`inToRec`。新規。記録モードにして `#in-t` に焦点を当てる)。履歴モードの「選ぶ」(複数選択)は履歴モードの見出し左側に残す(`inLead` の置き場所は担当が決めてよいが、44px 以上・見出しに収まること)
- 「確定」ボタン(`#in-ops` の主): `inRecord()`。押せる条件は今の「記録する」と同じ。「下書き保存」(副): `inSend()`。文が空なら押せない。どちらも押した後は **記録モードのまま**、入力欄は空、結果は `#in-undo` に1行(取り消し付き)
- 札(`.in-cards`)の見た目は今のものを引き継ぐ(強い読み=面、弱い読み=点線 `--read`、雑記のまま=文字だけ、日記ヒント=「日記に書く」、小札は押して取り消し・戻し、44px)。ただし `max-height:34vh` は外し、①の高さいっぱいを使う

## 5. 読み取り v3 — 行ごとのプロパティ(担当 A: js/m-inbox.js)

INPUT2.md §1 の「区切りで読む(文中の語も、独立した語なら読む)」を **やめて**、次に置き換える。`readText` / `readBlocks` / `jotAddMany` / `diaryAppend` / `ruleCandidates` の **名前と戻りの形は変えない**(`marks` に `line`(行番号)を足し、`role` に 'dt'・'tag' を足してよい)。

### 5.1 決まり
1. **空行で分けた1ブロック = 1記録**(今のまま)。ブロックの中の **改行1つ = 行の区切り**
2. **題 = 最初の「題でない行」でない最初の行**。つまり `#` で始まる行(タグの行)と、種類の行(下の 種類)は題にならず、それらを除いた **最初の行が題**(「10/30の買い物」は題。「今日は楽しかった」も題。「#プロジェクト⏎ピクミン3 全フルーツ回収最速クリア」は 題=ピクミン3…、タグ=プロジェクト)。題の中の日付・数字・時刻・金額・種類の語は **読まない**
3. **題より後ろの行 = プロパティの行**(タグの行 `#名前` だけは題の前=1行目にあってもよい)。1行が1つのプロパティ(次の形に **行全体が** 合う時だけ読む。合わない行は **備考** としてメモ欄に残す。捨てない)
   - **日付・時刻**: `日付 [時刻]` / `日付` / `時刻`。日付は `M/D`(10/30)、`/D`(今月のD日)、`D日`、`今日 明日 明後日 昨日`、`+N` `-N`(**前の日付の行**から N日。前が無ければ今日から)。時刻は `H:MM` / `H時` / `H時MM分`。日付だけの行は終日、時刻だけの行は直前の日付と同じ日
   - **終わり**: 日付・時刻の行が2つあれば、1つ目=始まり、2つ目=終わり(2つ目に日付が無ければ始まりと同じ日。「/10 19:30」の次の「+0 20:30」は同じ日の20:30まで)
   - **金額**: `¥850` `￥850` `850円` `850`(数字だけの行。1900〜2100 の4桁は年に見えるので金額でなく備考)
   - **タグ**: `#名前`(1行に複数可。**種類にはならない**=種類の決めから外す。ToDo/メモのタグ。タグの行は1行目にあってもよい)
   - **1行に複数のプロパティ**: 行を空白で分けた各語が **全部** 日付・時刻・時刻の範囲(`10:00-11:00` `10:00〜11:00`)・金額・タグのどれかに合う時だけ、その行を読む(例 `¥850 #外食`、`明日 10:00-11:00`)。1語でも合わなければ行全体が備考(文章は読まない)
   - 時刻の範囲は 始まり〜終わり(同じ日)
   - **種類**: 行がまるごと「予定 出来事 ToDo メモ 支払い 日記」、または「種類:メモ」「種類：予定」の形 → 種類を決め打ち(`o.type` が優先)。メモの時、`#名前` の行はメモのタグ(分類。メモの既存の欄に合わせる。担当が決めて報告)、題以降の本文はメモの本文
4. **種類の決め方**(決め打ちが無い時): 金額の行がある → 支払い。**時刻がある**日付・時刻の行がある → 始まりが基準より後なら予定、過去なら出来事。**日付だけ**の行(時刻なし)は、今日以降なら ToDo の期限、過去なら出来事(終日)。タグの行だけある → ToDo。どれも無い → 記録にならない(`cand=null`、`conf='none'`。雑記のまま)
5. **強い/弱い**: プロパティの行から決まった種類は `strong`。題だけは、`o.type` がある時だけ `strong`、無ければ `none`。weak は作らない
6. **感想のヒント**: プロパティの行が1つも無く(題だけ)、題の文末が感想の言葉(INPUT2.md の決め 0 と同じ語)なら `hint='diary'`、`hintDate` は基準の日付

## 6. 音声(担当 C: js/voice.js)の追加
- 認識の確定(isFinal)1件ごとの区切りを **改行** にする(INPUT2.md §3 の「確定どうしは空白」を **やめる**)。話の間(ま)がそのままプロパティの区切りになる(「ランチ」…間…「850円」→「ランチ⏎850円」)
- 「改行」「かいぎょう」と話した確定は文字にせず、**区切りの改行の代わり**(間と同じ。余分な改行を足さない)にする。**空行(=次の記録)ができるのは「改行」を2回続けて話した時だけ**。認識の再開の境目は、間と同じ1つの改行
- 数字の整え: 確定の文字の中の漢数字(「八百五十円」「十時」「三千円」)を、円・時・分の前後に限って算用数字に直す(〜万・千・百・十と一〜九・〇。例 八百五十円→850円、十時三十分→10時30分)。数字の間の空白は詰める(「8 50円」→「850円」)
- composer の `onText` の渡し方は今のまま。入力欄側(B1 の `inAppend`)は「前が空でなければ改行を挟んで」足す
